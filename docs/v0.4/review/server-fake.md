5. **[medium] src/llm_configurator/llama_server.py:181** — If the app is ended by SIGTERM or SIGHUP (terminal window closed, logout, `kill`), llama-server keeps running and holds RAM, VRAM and its port. The child runs in its own session, the app installs no signal handlers, and atexit does not run on a fatal signal.
   - Evidence: Reproduced. A parent Python process started LlamaServer(fake_command('server')) and was then sent SIGTERM, and in a second run SIGHUP. Both times the output was 'llama-server child <pid> STILL RUNNING after parent died'. `grep signal src/` finds no handlers. start_new_session=True (line 181) means a terminal hang-up never reaches the child. On Windows the child is started with CREATE_NO_WINDOW|CREATE_NEW_PROCESS_GROUP, so closing the console or ending the app in Task Manager leaves it running as well. The next start then runs out of memory, or another program ends up talking to the leftover server (see the port finding).
   - Suggested fix: Add `llama_server.install_exit_handlers()`, called from the main thread by cli.main and app.serve. It should map SIGTERM and SIGHUP (and SIGBREAK on Windows) to `sys.exit(128 + signum)`, so that atexit's _stop_all runs. On Windows, also assign each spawned process to a Job Object with JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE (via ctypes), so the server dies with the app.
