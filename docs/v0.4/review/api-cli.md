4. **[medium] src/llm_configurator/cli.py:512** — `export --output x.ps1` writes UTF-8 without a BOM, then prints export's own note telling the user to save it as "UTF-8 with BOM". Windows PowerShell 5.1 misreads non-ASCII model paths in such files. The unaddressed export Request (utf-8-sig for .ps1, 0755 for .sh) applies.
   - Evidence: cli.py:512: `args.output.write_text(result["content"], encoding="utf-8")`. Repro with a model in `Modèles/`: the saved start2.ps1 starts with `b'# S'` (no BOM), and stderr prints "The script contains non-English characters. Save it as \"UTF-8 with BOM\" so Windows PowerShell 5.1 reads the path correctly". A .sh written this way is mode 0644. On Windows, text mode also turns \n into \r\n, which breaks a `--platform posix` bash script (`$'\r': command not found`).
   - Suggested fix: `enc = "utf-8-sig" if result["filename"].endswith(".ps1") else "utf-8"; args.output.write_text(result["content"], encoding=enc, newline="\n" if not result["filename"].endswith(".ps1") else None)`. Then `if result["filename"].endswith(".sh") and os.name != "nt": args.output.chmod(0o755)`. Leave out the BOM note when the CLI already wrote the BOM.
