1. **[high] src/llm_configurator/llama_server.py:176** — Every llama-server the app starts (the user's long-running server from /api/serve/start, plus the servers used by tests, quizzes and compares) runs with llama.cpp's default CORS setting, which allows every origin. So any website open in the user's browser can call the local model and read its replies. The UI tells the user 'Only apps on this computer can reach it.'
   - Evidence: Harness help-llama-server.txt:479-493: `--cors-origins ORIGINS ... (default: *)`, and `--cors-credentials ... default: enabled ... if ... --cors-origins is set to * (default), the Origin header will be echoed back, and credentials will always be allowed`. Harness server-log.txt: `W srv llama_server: CORS is set to allow all origins ('*') and no API key is set` / `this can be a security risk (cross-origin attacks)`. launch.server_args (launch.py:79-113) and server_env (launch.py:116-122) never set --cors-origins or LLAMA_ARG_CORS_ORIGINS, and LlamaServer._spawn (llama_server.py:176-177) passes launch.server_env unchanged. server.py:227-232 (serve_start) runs this server with no time limit. /slots is also enabled by default (help:578). run.js:1295 promises: "Only apps on this computer can reach it."
   - Suggested fix: In LlamaServer._spawn, start the child with `options["env"] = {**launch.server_env(config), "LLAMA_ARG_CORS_ORIGINS": "localhost"}`. Per the help text, 'localhost' reflects the Origin header only for localhost. Using the environment variable instead of a flag means older builds that lack the option just ignore it, rather than failing with 'unknown argument'. Optionally also set LLAMA_ARG_ENDPOINT_SLOTS=0 for the managed server.

2. **[high] src/llm_configurator/server.py:580** — serve() only handles KeyboardInterrupt. Closing the terminal window (SIGHUP) or a plain `kill` (SIGTERM) ends the app without running server_close() or atexit. The user's llama-server is started in its own session or process group, so it keeps running with no owner, holding GBs of RAM/VRAM and an open port (with CORS *).
   - Evidence: server.py:586-591: `try: server.serve_forever() except KeyboardInterrupt: pass finally: server.server_close()`, with no signal handlers. llama_server.py:178-181 starts llama-server with `start_new_session=True` (POSIX) or `CREATE_NEW_PROCESS_GROUP` (Windows), so terminal signals don't reach it. The atexit hook at llama_server.py:371 does not run when a signal kills the process. Reproduced in the scratchpad: started a server through /api/serve/start, ran serve_forever in the main thread as serve() does, sent SIGHUP to the app. The app exited with code 129, and `ps` then showed the llama-server process alive with PPID 1 (`10927 1 10927 ... fake_llama.py --as server ... --port 40483`).
   - Suggested fix: Before serve_forever in serve(), install handlers that turn termination signals into the existing clean path. For example: `def _stop(*_): raise KeyboardInterrupt`, then `for name in ("SIGTERM", "SIGHUP", "SIGBREAK"): sig = getattr(signal, name, None); sig and signal.signal(sig, _stop)`. The finally block then calls server_close(), which stops the registry.
